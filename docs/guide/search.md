# Guide search and regex workbench

The Home catalogue search matches card names, identifiers and their displayed details. The same field also lists matching wiki articles. Each wiki route provides a full-guide search covering all six source articles and the catalogue, with links to the matching article or card. Plain text matching is case insensitive and is the default.

The **Regex builder** button sits beside each search field. It opens an anchored workbench for that field, with a pattern editor, JavaScript flags, construct insertion, sample text, match positions and captures, replacement preview, timing, and local snippet import/export. Turning on regex mode makes the field and pattern editor reflect the same text. An invalid pattern displays the browser's validation message and matches nothing until corrected. Closing the builder returns keyboard focus to the search field.

JavaScript `RegExp` is the engine. Its feature list depends on the visitor's browser. Atomic groups, possessive quantifiers, conditionals, subroutines, and inline modifiers are unavailable in this engine. Set operations in character classes require support for the `v` flag. JavaScript does not expose a parse tree or step trace. Complex expressions can take a long time; the workbench limits its live sample display to 100 matches, but users should still avoid untrusted complex patterns. Search, samples and snippets are handled locally, without a search service or analytics request. Saved snippets use this browser's local storage and can be exported or cleared through browser storage controls.

Build the static index from the reviewed article source with `node tools/build-wiki.mjs`. Run `node tools/check-search.mjs` for the hand-written Home and wiki route inventory, matcher behavior, invalid pattern handling and cross-page wiring. Run `node tools/check.mjs` for the existing catalogue and version checks. Those source checks do not prove rendered browser behavior; a hidden browser run and reviewed captures are needed for that claim.
